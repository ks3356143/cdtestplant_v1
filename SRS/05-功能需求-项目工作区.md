# 05 功能需求-项目工作区

> 路由：`/project`（PROJECT_LAYOUT，含子路由 round/dut/designDemand/testDemand/case/problem/opeSets）
> 后端：`apps/project/controllers/`（round.py、dut.py、design.py、testDemand.py、case.py、problem.py、treeOperation.py）

## 1. 工作区布局与轮次树

### 1.1 布局

- **顶栏**：项目设置按钮（含绿色校验状态徽章）、项目名称显示
- **左侧树滑块（treeSlider）**：搜索框、搜索按钮、「全部展开」、「点击复制创建轮次」
- **树节点**：根为轮次（第1轮测试/第2轮测试…），每节点带：
  - 复选框（用于复制/移动等批量操作的目标选择）
  - 展开箭头（展开显示被测件→设计需求→测试项→用例四级子树）
  - 快捷图标：查看轮次表单、（数据）流转、编辑、删除、新增子节点
  - 「右键」提示：右键节点弹出上下文菜单（新建子级、复制、删除、重命名等）
- **右侧内容区**：随树选中节点切换为 轮次表单 / 被测件 / 设计需求 / 测试项 / 用例 / 问题单 的表单或表格（ma-form / ma-crud 动态渲染）；节点上的悬浮预览（ParentPreview + ma-info）展示上级节点信息

### 1.2 树 key 约定

- 每个节点 `key = 父key-自身序号`，`level`：轮次=1、被测件=2、设计需求=3、测试项=4？实际约定为 round=1、dut=2、design=3、testDemand/case 按深度（代码默认 level：dut 1、design 2、testDemand 3、case 4）
- 树数据由后端拼装返回（`getRoundInfo`、`getCaseInfo`、`getTestdemandInfo`、`getDesignDemandInfo` 均返回 TreeReturn 结构）
- 复制/移动子树：`POST /api/treeOperation/copy`

## 2. 轮次信息（/project/round）

- 表单字段：轮次标识、轮次名称、等级（grade）、执行地点（location）、最优/典型/最低工况的电压与温度（best/typical/low_condition_voltage、_tem）
- 轮次 beginTime/endTime 自动记录（auto_now_add）
- 操作：新增、编辑（PUT /project/round/update/{id}）、删除（DELETE /project/round/delete，可带级联选择）、复制创建轮次（点击复制创建轮次按钮）
- **影响域分析（第二轮起）**：
  - `GET /api/project/round/get_influence` 影响项列表
  - `GET /api/project/round/get_status_influence` 影响状态
  - `POST /api/project/round/create_influence` 新建影响项（更改类型、更改内容描述、影响域分析、影响用例集合 effect_cases）

## 3. 被测件（/project/dut）

- 表单字段：被测件标识、类型（如 源代码/CPU/FPGA/软件文档 等）、名称、树标题、版本、发布单位、发布时间、文档编号 ref
- **代码规模**（2025-04 起）：总行数、有效代码行数、注释行数（手工或统计）
- **文件上传**：
  - `POST /api/project/upload_file`：被测件相关文件上传（FileInputModal）
  - `POST /api/project/upload_xq_docx/`：上传需求文档 docx（解析辅助建需求）
- **代码度量（DutMetrics，1:1）**：对源代码类被测件用 lizard 统计——模块数量、平均模块大小、平均圈复杂度、最大圈复杂度、圈复杂度>20 模块占比、平均扇出数、空行数
- **接口图素材**：被测件页维护 `POST /api/project/interface_image/`、`GET /api/project/get_interface_image/`（文档用接口图）

## 4. 设计需求（/project/designDemand）

- 字段：设计需求标识、名称、类型 demandType（1 功能 / 2 性能 / 3 接口 / 4 可靠性 / 5 安全性 / 6 静态类型）、章节号 chapter、描述（TinyMCE 富文本 HTML）
- **接口类（demandType=3）附加**：
  - 接口类型（type，长文本）、是否双向（is_bidirectional）
  - 接口方向信息 JKDesignInfo：正向/反向各一条（描述、来源 source、目的地 destination），同接口同方向唯一
  - `GET /api/project/create_renji/` 生成人机交互接口方向
- 树操作：`GET /api/project/getDesignDemandInfo`（树）、multi_save 批量建、`GET /api/project/designDemand/getRelatedDesign`（关联查询）、批量替换 `POST /api/project/designDemand/replace/`、`GET /api/project/copy_current`（复制当前）、`GET /api/project/switch_position`（位置交换）
- **AI 弹窗（AiModal）**：调用内网大模型按设计需求描述生成测试项草稿（见 09）

## 5. 测试项 / 测试需求（/project/testDemand）

- 字段：测试需求标识、名称、充分条件 adequacy、优先级 priority（高/中/低）、测试类型 testType（22 种）、测试方法 testMethod（多选 JSON）、测试项描述 testDesciption（新模板）、树 title/key/level
- **测试子项（TestDemandContent）**：子项名称 subName、一句话描述 subDescription（CPU/FPGA 渲染差异）
- **子项步骤（TestDemandContentStep）**：操作 operation（≤3072）、预期 expect
- 功能：

| 编号 | 需求 | 接口 |
|---|---|---|
| TD-01 | 列表/树查询 | GET /project/getTestDemandList、/getTestdemandInfo、/getTestDemandOne(ById) |
| TD-02 | 单建/批量建 | POST /project/testDemand/save、/multi_save |
| TD-03 | 编辑/删除 | PUT /project/testDemand/update/{id}、DELETE /project/testDemand/delete |
| TD-04 | 关联测试项（回归交叉引用） | GET /project/testDemand/getRelatedTestDemand、POST /solveRelatedTestDemand、POST /getExistRelatedTestDemand |
| TD-05 | 测试项转设计需求（复制） | POST /project/testDemand/copy_to_design |
| TD-06 | 批量替换文本 | POST /project/testDemand/replace/ |
| TD-07 | 批量替换优先级 | POST /project/testDemand/priorityReplace/ |

- **约束**：删除测试项时若其下已存在用例，返回错误码 40031（前端提示先处理用例）

## 6. 测试用例（/project/case）

- 字段：用例标识、名称、初始条件 initialization、前提和约束 premise、用例综述 summarize、设计人员 designPerson、测试人员 testPerson、审核人员 monitorPerson、执行时间 exe_time、FPGA 时序图 timing_diagram（富文本）
- **用例步骤（CaseStep）**：操作 operation（富文本）、预期 expect（≤3072）、结果 result（富文本）、是否通过 passed（1 通过 / 2 未通过 / 3 未执行）
- 功能：

| 编号 | 需求 | 接口 |
|---|---|---|
| C-01 | 列表/树查询 | GET /project/getCaseList、/getCaseInfo、/getCaseOne(ById) |
| C-02 | 单建/批量建 | POST /project/case/save、/multi_save |
| C-03 | 由测试项生成用例 | POST /project/case/create_by_demand |
| C-04 | 编辑/删除 | PUT /project/case/update/{id}、DELETE /project/case/delete |
| C-05 | 用例复制/移动（到测试项或用例间） | GET /project/case/copy_or_move_to_demand、/copy_or_move_by_case |
| C-06 | 批量替换（文本/负责人/执行时间） | POST /project/case/replace/、/personReplace/、/timeReplace/ |
| C-07 | 关联用例查询（问题单用） | GET /project/case/getRelatedCase |

- **执行记录**：直接在用例步骤上填写 result 与 passed，看板据此统计已执行/未执行

## 7. 问题单（/project/problem）

- 字段：问题单标识（PT_Rxxx_xxx，按测试项类型排序）、名称、状态 status、等级 grade、类型 type、闭环方式 closeMethod（多选 JSON）、问题描述 operation（富文本）、问题结果/影响 result（富文本）、提出人员/提单日期、开发人员/确认日期、验证人员/验证日期、改正措施 solve、原因分析 analysis、影响域分析 effect_scope、回归结果 verify_result
- **关联用例**：多对多（提出问题时勾选相关用例，ProblemChoose 选择器）
- 功能：

| 编号 | 需求 | 接口 |
|---|---|---|
| P-01 | 按项目查询问题列表 | GET /project/getProblemList |
| P-02 | 查询全部问题（跨轮次） | GET /project/problem/searchAllProblem |
| P-03 | 新建/编辑/弹窗编辑 | POST /project/problem/save、PUT /problem/update/{id}、PUT /problem/modalupdate/{id} |
| P-04 | 删除 | DELETE /project/problem/delete |
| P-05 | 问题关联用例 | GET /project/getRelativeCases |
| P-06 | 单条查询 | GET /project/getSingleProblem |
| P-07 | 关联问题列表（回归） | GET /project/problem/relateProblem |

- **闭环方式**（closeMethod 字典）：回归测试通过/评审通过/…（见附录）
- 状态流转：开放(2) → 关闭(1)/推迟(3)/撤销(4)；solve 字段要求关联 status=1（关闭）使用

## 8. 操作集合（/project/opeSets）

以表格为中心的批量操作工作区，聚合四张表（DesignTable/DemandTable/CaseTable/ProblemTable），每张表提供：

- **搜索表单 + 触发器（Trigger）**：条件联动刷新
- **列设置（Setting）**：自定义显示列
- **批量操作**：
  - 需求表：DesignForm/DemandForm 批量编辑、ReplaceModal 替换、ReplacePriority 优先级批量替换
  - 用例表：form 批量编辑、ReplaceExetime 执行时间批量替换、ReplacePerson 人员批量替换
- **父级信息联动**：表单内嵌 ParentPreview 悬浮查看上级（被测件/设计需求/测试项）信息
- 数据接口复用第 4~7 节的 CRUD 接口（getDesignDemandList / getTestDemandList / getCaseList / getProblemList）

## 9. 主要业务约束汇总

1. 树形数据必须先建上级（轮次→被测件→设计需求→测试项→用例），后端按外键级联
2. 测试项下有用例时不可直接删除（40031）
3. 用例/需求批量替换操作均为条件匹配 + 范围限定（防误替换）
4. 所有关键数据操作均被 ApiLoggingMiddleware 记录为接口操作日志；表格数据变更另记数据操作日志（operate_obj/operate_des）
