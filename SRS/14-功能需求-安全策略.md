# 14 功能需求-安全策略

> 路由：`/security/*`；菜单仅系统安全员（`secadmin`）可见（`web/cdTMP/src/router/routes/modules/security.js`）
> 后端：`apps/system/controllers/policy.py`、`secrecy.py`、`selfcheck.py`；权限类 `IsSecurityAdmin`
> 覆盖 GB/T 28452-2012 第三级 7.1.1 鉴别失败处置、7.1.4 标记管理、7.1.8 保密性、7.1.10 安全性检测分析

## 1. 登录失败锁定策略（/security/policy，7.1.1）

安全员配置鉴别失败处置策略，登录接口实时生效。

| 配置项 | 含义 |
|---|---|
| 登录失败最大尝试次数 `login_max_attempts` | 窗口内累计达到该值即锁定账号 |
| 失败统计时间窗口 `login_window_minutes` | 失败次数的累计窗口 |
| 账号锁定时长 `login_lock_minutes` | 触发锁定后禁止登录的时长 |

- 存储：`system_security_policy` 单例行（`SecurityPolicy.load()` 保证只有一条）
- 生效点：`MyTokenObtainPairInputSchema.authenticate()`（apps/user/schema.py）——锁定检查 → 失败累计（Redis 计数）→ 成功清零
- 触发锁定与失败均写登录日志，并在统一安全审计页产生告警（`account_lock` / `login_fail`）
- 页面按钮：**保存策略**（写库 + 审计留痕）、**重置**（恢复为上次保存值，撤销未保存的编辑）、**刷新**（重新读取）

| 接口 | 说明 |
|---|---|
| GET /api/system/security/policy 🛡 | 读取策略 |
| PUT /api/system/security/policy 🛡 | 更新策略（审计留痕，记录新旧值） |

## 2. 敏感标记管理（用户密级许可，7.1.4 / 7.1.5）

标记由系统安全员统一配置，管理员与普通用户无权修改；用户仅能访问密级不高于本人许可的项目数据，调整后立即生效。
唯一超级管理员账号 `superAdmin` 不参与标记管理。

| 接口 | 说明 |
|---|---|
| GET /api/system/security/clearance/list 🛡 | 全部用户的密级许可清单 |
| PUT /api/system/security/clearance/{user_id} 🛡 | 配置某用户的密级许可（审计留痕 + 数据操作日志） |

密级取值来自 `secret` 字典：1 公开 / 2 内部 / 3 秘密★5年 / 4 机密★10年 / 5 绝密★20年。

## 3. 数据保密性保护（7.1.8）

页面在同一路由下以「数据保密性保护」卡片呈现五个小节，供测评人员逐项核对：

| 小节 | 内容 |
|---|---|
| ① 存储保密性——已加密字段 | 由模型自动枚举（`EncryptedCharField`），保证文档与代码同源；当前为用户表 `phone`、`email` |
| ② 传输保密性 | 检测随附的 `deploy/https` TLS 反代配置与证书是否就位，展示协议版本与配置文件路径；云上以 nginx 443 站点提供服务，端口随部署形态不同（打包 8443 / 云上 443） |
| ③ 剩余信息保护措施 | 四条措施及其承担方（本平台 / 操作系统），应用层无法承担的如实标注 |
| ④ 临时文件清理 | 显示 `media/<R号>/temp`、`form_template/*/temporary` 的占用，可按保留期（全部/1 小时/24 小时/7 天）一键清理 |
| ⑤ 日志脱敏字段 | 写入操作日志前会被脱敏的字段清单 |

实现要点：

- 透明加密字段 `utils/crypto.EncryptedCharField`（Fernet = AES-128-CBC + HMAC-SHA256，带完整性校验），
  写库自动加密、读库自动解密；密文前缀 `enc:v1:`；密钥取 `FIELD_ENCRYPTION_KEY`，缺省由 `SECRET_KEY` 派生
- 历史明文由数据迁移 `apps/user/migrations/0009_encrypt_existing_sensitive_fields.py` 就地加密（可反向解密回滚）
- 加密列无法 `LIKE`，按电话检索改走 `Users.phone_index`（SHA-256 盲索引，`save()` 自动维护）
- 剩余信息清理 `apps/system/tools/residue.py`；登出接口同时清除本账号的服务端临时缓存键

| 接口 | 说明 |
|---|---|
| GET /api/system/security/confidentiality 🛡 | 保密性总览 |
| POST /api/system/security/residue/purge 🛡 | 清理过期临时文件（可传 `max_age_hours`） |

## 4. 安全性检测分析（/security/selfcheck，7.1.10）

一键自检，覆盖国标五个被测对象，逐项给出**结论（通过/风险/提示/不适用）**、检测方式、说明与整改建议；
并列出依据检测结论已落地的改进，形成"检测分析 → 改进"闭环记录。

| 被测对象 | 检测项 |
|---|---|
| 操作系统 | 运行模式（DEBUG）、应用密钥是否框架默认值、主机头白名单是否通配、敏感配置（.env）是否被版本库忽略 |
| 数据库 | 连接账号是否超级账号、口令强度、连通性（`SELECT VERSION()`）、会话连接是否启用 TLS；库层漏洞扫描标注不适用 |
| 网络 | 对外传输是否经 TLS 反代；网络设备与链路漏洞扫描标注不适用 |
| 应用系统 | 接口鉴别覆盖率（解析 OpenAPI 定义逐条判定）、口令存储哈希、鉴别失败锁定策略、特权账号双因子、敏感字段落库加密、安全审计、数据完整性标签、令牌有效期、剩余信息清理 |
| 硬件 | 电磁泄漏发射与电磁干扰检测标注不适用（由具备资质的检测机构/场地与设备管理机构承担） |

- 执行动作写统一审计（事件类型 `security_scan`，label「安全性检测分析」）
- 应用层之外一律如实标注承担方，不虚构能力；某单项检测异常不影响整份报告（逐项 try/except）

| 接口 | 说明 |
|---|---|
| GET /api/system/security/selfcheck 🛡 | 执行检测并返回检测项、汇总统计、改进记录 |
