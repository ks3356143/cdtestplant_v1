# 11 数据模型

> 数据库 `chengdu_test_plant_v1`（MySQL 8.4），43 张表。基类 CoreModel 统一提供：id（BigAutoField）、remark（描述）、update_datetime、create_datetime、sort（显示排序）。
> 树形数据通用字段：title（树显示名）、key（层级路径串）、level（层级）。

## 1. 实体关系总览

```
Project 1 ── N Round 1 ── N Dut 1 ── 1 DutMetrics
   │            │          │
   │            │          └── N Design 1 ── N JKDesignInfo（接口方向 0~2）
   │            │                 │
   │            │                 └── N TestDemand 1 ── N TestDemandContent 1 ── N TestDemandContentStep
   │            │                        │（otherDesign M2M Design）
   │            │                        └── N Case 1 ── N CaseStep
   │            │                               ▲
   │            └── 1 InfluenceArea ── N InfluenceItem
   │                                    │
   └──────────── N Problem ▲────────────┘  （Problem M2M Case）
        │
        ├── 1:1 ProjectSoftSummary（软件概述）── N StuctSortData
        ├── 1:1 ProjectDynamicDescription（动态环境）── N StuctSortData
        ├── 1:1 StaticSoftItem / StaticSoftHardware / DynamicSoftTable / DynamicHardwareTable / EvaluateData（JSON 表格素材）
        ├── 1:1 EnvAnalysis（环境差异性分析）
        ├── 1:1 StuctSortData（接口图）
        └── N Fragment（文档片段）
```

用户/字典/日志：Users、Dict 1—N DictItem、Contact、Abbreviation、LoginLog、OperationLog、TableOperationLog。

## 2. 测评业务表（apps/project）

### 2.1 project_project 项目信息（Project）

| 字段 | 说明 |
|---|---|
| ident | 项目标识（R 编号），唯一 |
| name | 项目名称 |
| beginTime / endTime | 起/止日期 |
| duty_person | 负责人 |
| member | 项目成员 JSON 数组 |
| quality_person / vise_person / config_person | 质量保证员 / 质量监督员 / 配置管理员 |
| security_level / test_level / plant_type / report_type | 安全等级 / 测试级别JSON / 平台类型JSON / 报告类型（9=鉴定） |
| language / standard | 被测语言JSON / 依据标准JSON |
| entrust_unit / entrust_contact / entrust_contact_phone / entrust_email | 委托方单位/联系人/电话/邮箱 |
| dev_unit / dev_contact / dev_contact_phone / dev_email | 研制方（开发方）单位/联系人/电话/邮箱 |
| test_unit / test_contact / test_contact_phone / test_email | 测试方（测评中心）单位/联系人/电话/邮箱 |
| step | 项目阶段（1 进行中 / 2 已完成 / 3 已废弃） |
| abbreviation | 缩略语 JSON（勾选自缩略语库） |
| soft_type | 软件类型 1 新研 / 2 改造 / 3 沿用 |
| runtime / devplant | 运行环境 JSON / 开发环境 JSON |
| secret | 密级（字典值） |

### 2.2 project_round 轮次信息（Round）

ident、name、beginTime/endTime、grade（等级）、最优/典型/最低工况电压温度（best/typical/low_condition_voltage、_tem）、location（测评执行地点）、project 外键、树字段（level/key/title）。

### 2.3 project_dut 被测件信息（Dut）

ident、type（被测件类型）、name、total_lines/effective_lines/comment_lines（总行数/有效代码行/注释行）、version、release_union（发布单位）、release_date、ref（用户文档编号）、project/round 外键、树字段。

### 2.4 project_dut_metrics 被测件代码度量（DutMetrics，1:1 Dut）

模块数量 function_count、平均模块大小 avg_function_lines、平均圈复杂度 avg_cyclomatic、最大圈复杂度 max_cyclomatic、圈复杂度>20 模块占比 high_cyclomatic_ratio、平均扇出数 avg_fan_out、空行数 total_blanks。（由 lizard 静态统计生成）

### 2.5 project_design 设计需求（Design）

ident、name、demandType（1功能/2性能/3接口/4可靠性/5安全性/6静态类型）、description（富文本）、chapter（章节号）、接口类附加：type（接口类型）、is_bidirectional（是否双向）；project/round/dut 外键、树字段。

### 2.6 接口方向信息（JKDesignInfo）

所属接口 Design 外键、direction（forward 正向 / reverse 反向）、description、source（来源）、destination（目的地）；(jk, direction) 唯一。

### 2.7 测试项三表

- **TestDemand（测试项）**：ident、name、adequacy（充分条件）、priority（1高/2中/3低）、testType（测试类型字典）、testMethod（JSON 多选）、testDesciption（测试项描述）、project/round/dut/design 外键、otherDesign（M2M Design 关联设计需求）、树字段
- **TestDemandContent（测试子项）**：subName（子项名称）、subDescription（一句话描述）、testDemand 外键
- **TestDemandContentStep（子项步骤）**：operation（操作 ≤3072）、expect（预期）、testDemandContent 外键

### 2.8 project_case 测试用例（Case）+ CaseStep

- Case：ident、name、initialization（初始条件）、premise（前提和约束）、summarize（用例综述）、designPerson/testPerson/monitorPerson（设计/测试/审核人员）、exe_time（执行日期）、timing_diagram（FPGA 时序图富文本）、isLeaf、project/round/dut/design/test 外键、树字段
- CaseStep：operation（操作富文本）、expect（预期 ≤3072）、result（结果富文本）、passed（1 通过 / 2 未通过 / 3 未执行）、case 外键（related_name=step）

### 2.9 project_problem 问题单（Problem）

| 字段 | 说明 |
|---|---|
| ident | 问题单标识 PT_R{项目}_{序号} |
| name | 问题单名称 |
| status | 1 关闭 / 2 开放 / 3 推迟 / 4 撤销 |
| grade | 1 一般 / 2 严重 / 3 建议 / 4 重大 |
| type | 1 其他 / 2 文档 / 3 编码 / 4 设计 / 5 需求 / 6 数据 |
| closeMethod | 闭环方式 JSON 多选 |
| operation / result | 问题描述（富文本）/ 问题结果与影响（富文本） |
| postPerson / postDate | 提出人员 / 提单日期 |
| designerPerson / designDate | 开发人员 / 确认日期 |
| verifyPerson / verifyDate | 验证人员 / 验证日期 |
| case | M2M 关联用例 |
| solve | 改正措施（开发方填写，status=1 时使用） |
| analysis | 原因分析（富文本） |
| effect_scope | 影响域分析（富文本） |
| verify_result | 回归结果（富文本） |

### 2.10 回归影响域

- **round_influence_area（InfluenceArea）**：round 1:1（第二轮起）
- **InfluenceItem**：influence 外键、change_type（更改类型）、change_des（更改内容描述富文本）、change_influ（影响域分析文本）、effect_cases（受影响用例 key 数组 JSON）

### 2.11 文档素材表（项目 1:1，结构统一）

StaticSoftItem（静态软件项）、StaticSoftHardware（静态硬件项）、DynamicSoftTable（动态软件项）、DynamicHardwareTable（动态硬件项）、EvaluateData（测评数据）——均为：table（JSON 二维数组）、fontnote（题注）、rounds_map（行选中轮次索引 JSON）。

ProjectSoftSummary（软件概述）、ProjectDynamicDescription（动态环境描述）：1:1 项目容器，内容以 StuctSortData 组织。

StuctSortData（data_schemas 结构化排序数据）：type（text 文本 / table 表格 / image 图片）、fontnote、content（JSON：文本内容或二维表或图片数据）；可挂 soft_summary / dynamic_description / project（接口图）三者之一。

EnvAnalysis（环境差异性分析表）：table JSON、fontnote、description（差异性分析文字）。

### 2.12 其他

- **contact_gongsi（Contact）**：单位库——name（公司名称）、refer_name（简称）、entrust_person（法人）、key（编号）、addr（地址）
- **project_abbreviation（Abbreviation）**：title（缩略语）、des（描述）

## 3. 用户与权限表（apps/user）

- **user_user（Users）**：继承 AbstractUser（username、password、email、is_active、is_staff、is_superuser、groups、user_permissions…）+ 扩展：name（姓名）、role（user/admin）、status、phone、avatar、job/jobName、organization、location(Name)、introduction、personalWebsite、accountId
- **user_user_groups / user_user_user_permissions**：Django 标准 M2M
- **operation_log（TableOperationLog）**：数据操作日志——user 外键、operate_obj（操作对象）、operate_des（操作详情）、create_datetime

## 4. 字典表（apps/dict）

- **system_dict（Dict）**：name（字典名称）、code（编码）、status、remark
- **system_dict_item（DictItem）**：title（显示名称）、key（实际值）、show_title（类型转文字）、status、dict 外键、remark、doc_name/publish_date/source（依据标准类专用）
- **fragment_core（Fragment，文档片段）**：name（片段名=文件名）、content（富文本 HTML）、is_main（是否覆盖磁盘片段）、project 外键；(name, project) 唯一

## 5. 日志与安全审计表（apps/system）

- **system_login_log（LoginLog）**：username、ip、agent、browser、os、country、login_type（1 普通登录）、remark、creator、update/create_datetime
- **system_operation_log（OperationLog）**：request_username、request_modular（请求模块）、request_path、request_body、request_method、request_msg、request_ip、request_browser、（OS）、响应状态、remark、creator、时间字段
- **system_audit_log（AuditLog，7.1.6）**：username/role/actor（主体）、event_type（EVENT_* 常量）、detail、success、ip、user_agent、create_datetime；仅追加，索引 create_datetime/event_type
- **system_data_integrity_tag（DataIntegrityTag，7.1.7）**：table_name + object_id（唯一）、digest（关键字段排序快照 SHA256）、algorithm、update/create_datetime；受保护数据（项目/用例/用例步骤/问题单）写后由信号自动刷新
- **system_security_policy（SecurityPolicy）**：登录失败锁定策略单例行（安全员维护）
- **project_nonrepudiation_evidence（NonrepudiationEvidence，7.1.2）**：evidence_type、actor、action、business、data_digest（SHA256）、content_snapshot、operation_ip

## 6. 建表与迁移

- 迁移文件随各 app 的 migrations/ 管理；生产初始化用 `packagesInitialize/dbdata.sql`（含 DROP TABLE，可重复导入）
- 各业务模型统一继承抽象基类 `utils/models.CoreModel`（不建表），提供公共字段：id、remark（描述）、sort（显示排序）、create_datetime、update_datetime
