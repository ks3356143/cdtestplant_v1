# 03 功能需求-首页与用户

## 1. 登录（/login）

### 1.1 功能描述

- 账号 + 密码 + 图形验证码登录；验证码为**前端画布生成、前端校验**（4 位字符，错误提示"验证码错误，请刷新后重试"）
- 登录成功返回 JWT token（响应字段 `data.token`），前端存 localStorage（key=`token`），后续请求以 `Authorization: token <JWT>` 携带（token 前缀由 `VITE_APP_TOKEN_PREFIX` 配置）
- 登录后自动跳转工作台，并展示用户姓名问候

### 1.2 认证链路

- 后端认证后端顺序：`django_auth_ldap.backend.LDAPBackend` → `django.contrib.auth.backends.ModelBackend`
- 内网环境走 AD 域账号（sAMAccountName 匹配，登录成功自动同步用户到本地库，不含密码）；域不可达时记录 `LDAPError` 警告日志并回落本地库校验
- 登录接口：`POST /api/system/login`，凭据错误统一返回 code=40001「账号或密码错误，如果是内网登录检查密码是否过期…」
- 登录行为写**登录日志**（用户名、IP、浏览器、操作系统、国家归属地等，见 08 文档）

## 2. 工作台（/dashboard/workplace）

页面组成：

1. **问候区**：用户姓名问候、平台标语（"好用的测试工具集 / 欢迎使用测试管理平台 ⭐长期更新"）、实时时钟与日期
2. **统计卡**（`GET /api/system/workplace/statistics`）：
   - 用户统计（用户总数）
   - 进行中项目数（step ∈ {1,2}）
   - 项目总数
   - 完成的项目数（step=3）
3. **项目每月统计图**（`GET /api/system/statistics/chart`）：按月统计项目创建数量的图表（vue-data-ui 渲染）
4. **系统公告**（`GET /api/system/getNoticeList`）：公告列表（当前为后端硬编码的版本发布公告），支持"更多"
5. **测试管理平台相关**：快捷入口卡片

## 3. 用户中心（/dashboard/usercenter）

- **个人信息**：查看/编辑个人资料（姓名、头像、电话、组织、住地、自我介绍、个人网站等 Users 表字段）
- **修改密码**：表单校验（新旧密码、确认密码），接口 `POST /api/system/user/modifyPassword`（管理员权限）及自助修改

## 4. 用户管理（/dashboard/usermanage，仅 admin）

用户列表 CRUD（对应 `apps/user` 接口，表 user_user）：

| 功能 | 接口 | 说明 |
|---|---|---|
| 用户列表 | GET /api/system/user/index、/list | 分页、检索 |
| 新建用户 | POST /api/system/user/save | 账号、姓名、角色（user/admin）、状态等 |
| 编辑用户 | PUT /api/system/user/update/{user_id} | — |
| 删除用户 | DELETE /api/system/user/delete | IsAdminUser |
| 启用/禁用 | GET /api/system/user/change_status | IsAdminUser |
| 修改密码 | POST /api/system/user/modifyPassword | IsAdminUser |
| LDAP 用户 | GET /api/system/user/ldap | 从域控查询用户（用于导入） |

- 用户字段：username（账号，唯一）、name（姓名）、role（角色）、status（启用状态）、phone、job/jobName、organization、location、email、avatar 等
- 前端操作含头像上传（ma-upload 组件）

## 5. 相关需求约束

1. 未登录访问任何受保护路由 → 重定向 /login；JWT 过期 → 请求拦截器清理 token 并回登录页
2. 非 admin 用户访问 admin 路由 → 按 roles 校验跳转到第一个有权限的路由
3. 用户信息接口 `GET /api/system/getInfo` 返回 Users 全字段（除密码）；email 必须为合法邮箱格式（pydantic 校验），否则接口 500——录入用户时需保证
4. 密码修改、用户删除等敏感操作需 admin 角色（前端按钮 + 后端 IsAdminUser 双重校验）
