# 12 非功能需求与系统约定

## 1. 统一响应格式

所有业务接口返回 `ChenResponse`（utils/chen_response.py，继承 HttpResponse）：

```json
{ "code": 200, "data": {...}, "message": "success", "success": true }
```

- 前端 axios 拦截器直接读取 `response.data`
- 日期序列化统一格式化为 `YYYY-MM-DD`（DateEncoder）
- JSON 解析/渲染使用 orjson（MyParser/MyRenderer，见 cdtestplant_v1/parser.py、renderer.py）

## 2. 错误码（utils/codes.py）

| code | 含义 |
|---|---|
| 40001 | 账号或密码错误（含内网登录密码过期提示） |
| 40031 | 测试项下已存在用例，禁止删除 |
| 40038 | 传给后端的数据越界 |
| 500412 | 项目结束时间早于最后一个轮次结束时间（看板校验，HttpError 特殊处理） |
| 502 | AI 大模型调用失败 |

- HttpError 的 status_code 被全局异常处理器转为业务 code（不使用 HTTP 状态码语义），HTTP 层统一 500/200

## 3. 认证与授权

- JWT：django-ninja-jwt，登录接口签发 access token；有效期 TOKEN_LIFETIME
- 请求头：`Authorization: Bearer <JWT>`（前端发送 "Bearer "+token）
- 认证后端：LDAP 优先（AUTH_LDAP_*，域 dns.paisat.cn:389，AlwaysUpdateUser 同步域用户资料），失败回落 ModelBackend；**内网无 LDAP 时本地数据库用户可登录**
- 权限控制：接口级 `auth=JWTAuth()` + 三权分立权限类（utils/permissions.py：IsSystemAdmin/IsSecurityAdmin/IsAuditor，按 Users.role 判定）；页面级前端路由 roles
- 特权角色（admin/secadmin/auditadmin）登录需图形验证码双因子；连续失败锁定（系统安全策略表，安全员配置）
- 中间件：SecurityMiddleware、CommonMiddleware、CsrfViewMiddleware（跨域策略放开 SECURE_CROSS_ORIGIN_OPENER_POLICY）、ApiLoggingMiddleware
- 密码：Django PBKDF2 哈希存储；修改密码走专用接口（登录用户自助，旧密码校验）

## 4. 日志体系

| 层 | 机制 | 去向 |
|---|---|---|
| HTTP 请求 | ApiLoggingMiddleware（排除 API_OPERATION_EXCLUDE_START 路径，映射 API_MODEL_MAP 模块名） | system_operation_log 表 + logs/root_log |
| 业务数据变更 | 各控制器显式写 TableOperationLog | operation_log 表 |
| 登录 | 登录接口写 LoginLog（含 IP 归属地解析，ENABLE_LOGIN_ANALYSIS_LOG） | system_login_log 表 |
| **统一安全审计（7.1.6）** | utils/audit.py 埋点（登录/标记/策略/账号管理/越权 403/日志清理） | system_audit_log 表（仅追加，仅审计员可查） |
| 应用日志 | LOGGING（conf/logConfig.py） | logs/root_log |

## 5. 缓存与性能

- Redis（django-redis，`redis://127.0.0.1:6379/1`）用于字典等热点数据缓存；不可用时相关接口报错（属依赖项非可选）
- 接口限流：apps/dict/throttle.py（字典模块限流配置）
- orjson 序列化 + 分页组件（chen_pagination.py）
- 通用 CRUD 封装（chen_crud.py）减少样板代码

## 6. 文件与存储

- 生成的文档与模板：`media/R{项目标识}/form_template/`（模板、临时片段）与 `media/R{项目标识}/final_seitai/`（成品）
- 上传文件：`uploads/`（URL `/uploads/{path}` 由 Django serve）
- 下载安全：一次性 download_token（Redis，10 分钟）换取文件流，兼容多进程
- 并发保护：文档生成事务 @transaction.atomic；文件被占用时明确报错

## 7. 兼容性与约束

1. 浏览器：现代 Chromium（Arco Design + Vite 目标）；登录页自适应窄屏
2. 时区：Asia/Shanghai（CELERY_TIME_ZONE，USE_TZ 配置见 settings）
3. MySQL 严格依赖 utf8mb4（导入需 --default-character-set=utf8mb4）；开发 3306、打包生产 3307、云上 3306
4. Python 锁定 3.13.x（requires-python >=3.13.11,<3.14）；依赖由 uv.lock 锁定
5. Celery 当前停用（`cdtestplant_v1/__init__.py` 中相关导入已注释），Redis 仅作缓存；如启用异步任务需恢复 celery 配置

## 8. 安全需求

1. **接口鉴别**：除 `POST /system/login`、`GET /system/captcha`、`POST /system/refresh`、
   `GET /create/download/{token}`（前端 iframe 拉取的一次性下载令牌，浏览器不带 Authorization）4 个入口外，
   全部 231 个接口要求 JWT 鉴别；覆盖情况可在「安全策略-安全性检测分析」页一键复核
2. 删除类/管理员操作双重校验（前端确认 + 后端权限类），按三权分立约束（见 03 文档第 4 节）
3. 项目数据自主访问控制与密级强制、统一审计与日志保护：见 `安全测评要求实现追踪表.docx` 与各功能文档对应小节
4. CSRF 中间件开启；X_FRAME_OPTIONS 默认
5. 密级字段（secret）贯穿项目与文档封面，导出文件按密级管理
6. **存储保密性（7.1.8）**：用户电话、邮箱落库透明加密（`utils/crypto.py`，Fernet），历史明文已迁移加密；
   加密列无法模糊匹配，按电话检索走 SHA-256 盲索引（`Users.phone_index`）
7. **日志脱敏（7.1.8）**：请求参数写入 `system_operation_log` 前统一脱敏（`utils/sensitive.py`）：
   口令/令牌类整体掩码、手机号保留前 3 后 4、邮箱保留首字符与域名
8. **剩余信息保护（7.1.8）**：缓存键统一 5 分钟过期（`CACHES.TIMEOUT`）；登出清除本账号临时键；
   文档生成中间产物按保留期清理（`manage.py purge_residue`），输入模板与交付文档不清理；
   内存缓冲区与交换分区由运行时/操作系统回收（如实标注）
9. **传输保密性（7.1.8 b/e）**：由部署层承担——打包部署用 `deploy/https`（nginx TLS 反代，8443），云上为 nginx 443 站点（TLSv1.2/1.3）；两处均不让应用直接对外提供明文入口，8081 只做 301 跳转；
   应用层不提供对外明文 HTTP 入口
10. **备份与故障恢复（7.1.9）**：业务数据可全量/增量备份为 JSON（含 SHA-256 摘要），恢复前校验摘要、
    按主键 upsert；定时增量见 `manage.py auto_backup`
11. **安全性检测分析（7.1.10）**：一键自检覆盖操作系统/数据库/网络/应用系统/硬件五类被测对象，
    应用层之外如实标注承担方；检测动作写审计
12. 生产打包需移除 staticfiles/TEMPLATES 调试项与 Swagger（settings.py TODO）

## 9. 可维护性约定

- 后端：apps 分域 + controllers 按业务域分文件 + controllers/__init__ 汇总（auto_discover_controllers 自动发现）
- 前端：views 按菜单域分组；api/ 按模块分文件封装；ma-crud/ma-form 通用组件驱动表格/表单
- 数据库表均带中文 verbose_name（可读性）；代码注释中文
- 版本：前端 package.json v0.1.2 与界面显示一致；变更记录见 README（change_log）

## 10. 环境配置与运维命令（2026-10-19 起）

凭据与部署相关配置不再写死在源码中，统一由项目根目录的 `.env` 提供（样例见 `.env.example`，
`.env` 已加入 `.gitignore` 不入版本库）。`conf/env.py` 通过 `django-environ` 读取，缺省值保证本地开发开箱可用。

| 变量 | 用途 | 缺省 |
|---|---|---|
| `DJANGO_SECRET_KEY` | 应用密钥（签名令牌、派生字段加密密钥） | 源码内置的开发值 |
| `FIELD_ENCRYPTION_KEY` | 用户敏感字段落库加密密钥（7.1.8） | 由 `DJANGO_SECRET_KEY` 派生 |
| `ALLOWED_HOSTS` | 主机头白名单（逗号分隔） | `*` |
| `DATABASE_HOST/PORT/USER/PASSWORD/NAME` | 数据库连接 | 127.0.0.1 / 3306 / root / root / chengdu_test_plant_v1 |
| `AUTH_LDAP_*`、`BASE_DN`、`FILTER_STR` | LDAP 域认证 | 见 `conf/env.py` |

> ⚠️ `FIELD_ENCRYPTION_KEY` **一旦变更，历史电话/邮箱密文将无法解密**，更换前务必先备份数据。
> 生产环境应使用只对本库授权、非 root 的数据库账号（本地演示环境已建 `cdtestplant_app`）。

管理命令：

| 命令 | 用途 |
|---|---|
| `python manage.py auto_backup [--kind full\|incremental] [--project ID]` | 定时备份（7.1.9），交计划任务调用 |
| `python manage.py purge_residue [--hours 24]` | 清理过期临时文件（7.1.8 剩余信息保护） |
| `python manage.py migrate` | 数据库迁移（含敏感字段就地加密迁移） |
