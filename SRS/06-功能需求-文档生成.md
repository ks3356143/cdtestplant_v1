# 06 功能需求-文档生成

> 后端：`apps/createDocument`（章节片段生成）+ `apps/createSeiTaiDocument`（正态文档组装、上传、下载）
> 前端入口：项目管理行内「文档生成」按钮 → GeneratorModal（按文档类型的上传下载弹窗）

## 1. 总体机制（两段式生成）

```
项目数据 ──► ① 章节片段生成（createDocument）
             读取项目/轮次/需求/用例/问题数据，逐章渲染为 docx 片段
             写入 media/R{id}/form_template/{bg|dg|sm|jl|hsm|hjl|wtd}/temporary/
                 │
用户上传的成品模板（media/R{id}/form_template/products/*.docx）
文档片段富文本（fragment_core 表 + temporary 片段文件）
                 │
             ② 正态文档组装（createSeiTaiDocument）
             模板 + 全部片段 docxcompose 合并
             → jinja stdContent 单字段二次渲染（text_frag_replace_handle）
             → 保存 media/R{id}/final_seitai/{文档名}.docx
             → 返回 download_token
                 │
             ③ 下载 GET /api/create/download/{token}
```

- **片段覆盖选取**：生成前前端拉取 `GET /api/createfragment/get_fragments`，列出已编辑片段供勾选（"首次生成请全勾选"），勾选结果随生成请求（payload.frag）提交——决定哪些章节用最新数据重新生成、哪些保留人工编辑
- **下载令牌**：`generate_download_token(file_path)` 生成短期 token，避免直接暴露路径；`GET /api/create/download/{token}` 校验后以文件流返回（文件名、Content-Disposition）
- **文件占用保护**：目标文件被 Word 打开时保存失败，返回「模版文件已打开，请关闭后再试」

## 2. 生成入口（7 类文档）

| 文档 | 组装接口 | 请求体 | 产出文件名 |
|---|---|---|---|
| 测评大纲 | POST /api/create/dgDocument | {id: 项目id, frag: [片段名…]} | 测评大纲.docx |
| 测试说明 | POST /api/create/smDocument | 同上 | 测试说明.docx |
| 测试记录 | POST /api/create/jlDocument | 同上 | 测试记录.docx |
| 测评报告 | POST /api/create/bgDocument | 同上 | 测评报告.docx |
| 第N轮回归测试说明 | POST /api/create/hsmDocument | {id, round_num, frag} | 第{N}轮回归测试说明.docx |
| 第N轮回归测试记录 | POST /api/create/hjlDocument | {id, round_num, frag} | 第{N}轮回归测试记录.docx |
| 问题单 | POST /api/create/wtdDocument | {id, frag} | 问题单.docx |

- 鉴定/第三方差异：项目 `report_type='9'` 视为**鉴定测试**（模板文案"装备鉴定和列装定型"、"鉴定"字样），否则为**第三方测试**（"软件交付和使用"、"第三方"）
- 密级文案：由项目 secret 字典值渲染到封面（如 秘密★5年）
- 时间变量：DocTime 工具按项目/轮次/文档历史计算各文档的编制、评审、起止时间占位

## 3. 章节片段接口清单（createDocument）

每个 `GET /api/{前缀}/create/{章节}` 生成该章节片段（返回片段文件），章节内容全部由项目实时数据计算：

### 3.1 测评大纲 /api/generate/*（dg.py，30+ 章节）

基本信息、技术依据 techyiju、任务来源、时间地点 timeaddress、被测软件指标 indicators、软件构成 softComposition、接口 interface、性能 top_file、静态环境（环境/软件/硬件 static_env/static_soft/static_hard）、动态环境（dynamic_env/dynamic_soft/dynamic_hard）、测试数据 test_data、环境差异 env_diff、基本信息合版 baseInformation、级别与类型 levelAndType、测试策略 strategy、充分性与有效性 adequacy_effectiveness、测试分组 group、质量保证 guarantee、缩略语 abbreviation、需求正向追踪 yzComparison、需求反向追踪 xqComparison、反向（fanXqComparison）、代码质量 codeQuality 等

### 3.2 测评报告 /api/generateBG/*（bg.py，15+ 章节）

删除重生成 deleteBGDocument、技术依据、时间地点、基本信息、完成情况 completionstatus、测试汇总 summary、测试内容与结果（contentandresults_1/2）、问题统计 problem_statistics、充分性与有效性 effect_and_adquacy、需求有效性 demand_effective、质量评价 quality_evaluate、整版 entire、需求追踪 yzxq_track、遗留问题汇总 problems_summary、修改清单 modi_list

### 3.3 测试说明 /api/generateSM/*（sm.py）

技术依据、用例清单 caseList、用例简表 caseBreifList、需求追踪 smtrack

### 3.4 测试记录 /api/generateJL/*（jl.py）

用例执行记录 caserecord（步骤、操作、预期、实际结果、通过状态）

### 3.5 第N轮回归测试说明 /api/generateHSM/*（hsm.py）

删除重生成 deleteHSMDocument、静态/动态软硬件、测试数据（与大纲同名的 5 个章节）、基本信息、文档说明 docsummary、测试技术 jstech、变更部分 changePart、回归需求 hdemand、用例说明 caseListDesc、用例清单 caseList、追踪 track

### 3.6 第N轮回归测试记录 /api/generateHJL/*（hjl.py）

删除重生成 deleteHJLDocument、基本信息 basicInformation、用例记录 caseinfo

### 3.7 问题单 /api/generateWtd/*（wtd.py）

问题单正文 problem（单条问题的完整描述表）

## 4. 模板与片段管理

### 4.1 模板上传

- `POST /api/documentUpload/file?id={项目id}&documentType={文档名}`：上传 .docx 模板（GeneratorModal 的 a-upload，limit=1）
- 回归说明/回归记录使用专用 `HgDocUpload` 组件（按项目 + 文档类型 + 轮次处理）
- 模板存放：`media/R{id}/form_template/products/{测评大纲|测试说明|测试记录|测评报告|第N轮回归测试说明|第N轮回归测试记录|问题单}.docx`

### 4.2 文档片段（fragment_core）

- 字段：name（片段名=章节文件名）、content（TinyMCE 富文本 HTML）、is_main（是否覆盖磁盘片段）、project（外键）；(name, project) 唯一
- 人工维护接口（/api/system/userField/*，前端「项目文档片段」页 /projFragment/:projectId）：
  - GET /api/system/userField/getFragment 片段列表
  - POST /api/system/userField/add 新建
  - PUT /api/system/userField/update/{id} 编辑
  - DELETE /api/system/userField/delete 删除
- 生成时读取接口：GET /api/createfragment/get_fragments（列出可覆盖片段）、GET /api/createfragment/get_round_exit（轮次退出信息）

## 5. 文档生成功能需求汇总

| 编号 | 需求 | 说明 |
|---|---|---|
| DG-01 | 上传各文档模板 | docx，单文件替换 |
| DG-02 | 勾选片段覆盖 | 首次全勾选；之后可保留人工编辑章节 |
| DG-03 | 一键生成并下载 | 生成 → token → 浏览器下载 .docx |
| DG-04 | 重生成指定文档 | deleteBGDocument/deleteHSMDocument/deleteHJLDocument 清理旧片段后重生成 |
| DG-05 | 回归文档按轮次生成 | round_num 参数（第2/3轮…），模板按轮次命名 |
| DG-06 | 人工编辑片段 | projFragment 页富文本编辑，下次生成可覆盖 |
| DG-07 | 生成失败反馈 | 数据缺失/模板缺失/文件占用分别提示 |
| DG-08 | 文档时间管理 | 看板文档时间轴 + DocTime 计算编制/评审时间 |
