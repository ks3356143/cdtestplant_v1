## 一句话概括

面向软件测评机构的**测评过程管理与文档自动生成平台**：管理测评项目、测试轮次、被测件、测试需求（设计需求→测试项→测试用例）、问题单，并基于项目数据 + 可编辑文档片段 + docx 模板，一键生成符合测评大纲/测试说明/测试记录/测评报告/回归测试文档/问题单等格式的 Word 文档。

## 核心概念速查

- **项目（Project）**：一次测评任务，以 `Rxxxx` 项目标识唯一（如 R2601）
- **轮次（Round）**：项目内的测试轮次（第一轮/第二轮/第三轮…），树形工作区的根
- **被测件（DUT）**：被测的软件/源代码单元，含代码规模与复杂度指标
- **设计需求（Design）**：被测件的设计需求（功能/性能/接口/可靠性/安全性/静态）
- **测试项（TestDemand）**：由设计需求导出的测试需求，含测试子项与步骤
- **测试用例（Case）**：测试项的具体执行用例，含步骤、执行结果
- **问题单（Problem）**：测试中发现的缺陷，全生命周期管理（开放→闭环/推迟/撤销）
- **文档片段（Fragment）**：文档某章节的可编辑富文本内容，是文档生成的素材
- **正态文档**：由模板 + 片段 + 项目数据组装生成的最终交付 Word 文档
