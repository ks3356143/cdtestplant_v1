# 02 总体业务流程

## 1. 测评业务全流程

```
立项建项目 ──► 进入项目工作区 ──► 逐轮次编写测试数据 ──► 执行与记录 ──► 问题闭环 ──► 文档生成 ──► 交付
```

### 阶段一：项目管理（测试管理 → 项目管理）

1. **新建项目**：填写项目标识（R 编号，唯一）、名称、起止时间、负责人、项目成员、质量保证员/质量监督员/配置管理员、委托方/研制方/测试方三方单位与联系人、安全等级、测试级别、平台类型、报告类型（鉴定/第三方）、被测语言、依据标准、密级、软件类型（新研/改造/沿用）、运行环境、开发环境等。
2. **项目管理列表**：多条件检索（标识/名称/起止时间/责任人/人员/状态/关键等级/类型/现状/密级），行内操作：**文档生成**、**工作区**（进入项目工作区）、复制项目、历史、参数、编辑、看板。

### 阶段二：项目工作区（树形结构）

点击「工作区」进入项目工作区（`/project` 布局）：左侧为**轮次树**，右侧为对应内容的表单/表格区。

- 树的根节点是轮次（第1轮测试、第2轮测试…），支持「点击复制创建轮次」（复制已有轮次快速建立新一轮）、「全部展开」、搜索、右键菜单
- 每个轮次节点下挂四类子数据：**被测件 → 设计需求 → 测试项 → 测试用例**，层级 key 形如 `roundKey-dutKey-designKey-testDemandKey-caseKey`（树级 level 0~4：轮次 0 / 被测件 1 / 设计需求 2 / 测试项 3 / 用例 4）
- 轮次信息表单：轮次标识/名称/等级/执行地点/最优·典型·最低工况（电压、温度）等

**第一轮（正式测试）**：

1. 录入**被测件**（DUT）：被测件类型/名称/版本/发布单位/发布时间/文档编号；源代码类被测件上传代码后由 lizard 统计**代码度量**（模块数、平均/最大圈复杂度、扇出、空行、代码行数），或手工录入
2. 逐个被测件录入**设计需求**：类型（功能/性能/接口/可靠性/安全性/静态），接口类需求录入接口方向信息（正向/反向、来源、目的地、是否双向）
3. 由设计需求生成/编写**测试项**（测试需求）：充分条件、优先级、测试类型（22 种字典值）、测试方法；测试项下建**测试子项**，子项下建**步骤**（操作、预期）；CPU/FPGA 项目可用 **AI 生成测试项**辅助
4. 由测试项生成/编写**测试用例**：初始条件、前提约束、综述、设计/测试/审核人员、执行时间、FPGA 时序图；用例下建**步骤**（操作、预期、结果、是否通过）
5. 测试执行：填写用例步骤的执行结果与通过状态（通过/未通过/未执行）

**第二、三轮（回归测试）**：

1. 复制第一轮数据建立回归轮次，或通过「点击复制创建轮次」快速派生
2. 第二轮起填写**影响域分析**（InfluenceArea/InfluenceItem）：更改类型、更改内容描述、影响域分析、受影响用例集合
3. 问题单回归：填写改正措施、原因分析、影响域分析、回归结果，推动问题闭环

### 阶段三：问题单管理

- 项目工作区内按被测件/设计需求维度提出问题单，关联多个用例
- 问题全生命周期：**开放 → 关闭 / 推迟 / 撤销**；等级（一般/严重/建议/重大）；类型（其他/文档/编码/设计/需求/数据）
- 开发方角色字段：改正措施（solve）、原因分析（analysis）、影响域分析（effect_scope）、回归结果（verify_result）

### 阶段四：文档生成（核心特色）

1. 点击项目行的「**文档生成**」打开生成弹窗（按文档类型 7 个入口）
2. **上传模板**：上传对应 docx 模板（首次）；回归文档由 `HgDocUpload` 处理
3. **片段覆盖选取**：列出该项目已编辑的文档片段，勾选需要被最新数据覆盖的片段（首次生成需全勾选）
4. 后端分两步：
   - **章节片段生成**（createDocument 应用，7 个控制器）：按章节把项目数据渲染成 docx 片段，写入 `media/R{id}/form_template/{模块}/temporary/`
   - **正态文档组装**（createSeiTaiDocument 应用）：读取 `form_template/products/` 的成品模板 → docxcompose 合并全部片段 → 对模板中 jinja 单字段（stdContent）二次渲染 → 保存到 `media/R{id}/final_seitai/` → 返回下载 token
5. 前端凭 token 调 `GET /api/create/download/{token}` 下载最终文档
6. 文档片段可随时在「项目文档片段」页（projFragment）人工编辑富文本，再次生成时覆盖

### 七类交付文档

| 文档 | 组装入口 | 片段控制器 | 内容要点 |
|---|---|---|---|
| 测评大纲 | POST /api/create/dgDocument | /api/generate/*（30+ 章节） | 项目信息、指标、软硬件构成、测试策略、充分性、缩略语、需求/反向追踪等 |
| 测试说明 | POST /api/create/smDocument | /api/generateSM/* | 技术依据、用例清单（详/简）、需求追踪 |
| 测试记录 | POST /api/create/jlDocument | /api/generateJL/* | 用例执行记录（步骤、结果） |
| 测评报告 | POST /api/create/bgDocument | /api/generateBG/*（15+ 章节） | 基本信息完成情况、结果汇总、质量问题统计、有效性/充分性、质量评价、遗留问题 |
| 第N轮回归测试说明 | POST /api/create/hsmDocument | /api/generateHSM/* | 变更部分、回归需求、用例清单、追踪 |
| 第N轮回归测试记录 | POST /api/create/hjlDocument | /api/generateHJL/* | 回归基本信息、用例记录 |
| 问题单 | POST /api/create/wtdDocument | /api/generateWtd/* | 问题单正文 |

## 2. 关键数据流转

- **树 key 机制**：所有树形数据的顺序与层级由字符串 `key`（`A-B-C-D-E` 逐级拼接）+ `level`（0~4）+ `title` 决定；树操作（复制/移动）后端整体重排 key
- **时间轴**：看板按项目开始时间、各轮次起止时间、文档生成时间绘制时间轴（`/api/testmanage/project/document_time_show`、`DocTime` 工具）
- **文档素材表**：软件概述、静态/动态软硬件项、测评数据、环境差异性分析等章节素材以「项目 1:1 表 + JSON 二维数组 + 题注 + 轮次映射」存储，前端以可编辑表格维护，生成文档时直接渲染
- **结构化排序数据**（StuctSortData）：软件概述/接口图/动态环境描述等章节支持文本、表格、图片三种内容块按序渲染

## 3. 状态字典（摘录）

- 项目阶段 step：1 进行中 / 2 已完成 / 3 已废弃
- 问题状态：1 关闭 / 2 开放 / 3 推迟 / 4 撤销；问题等级：1 一般 / 2 严重 / 3 建议 / 4 重大
- 用例步骤通过状态 passType：1 通过 / 2 未通过 / 3 未执行
