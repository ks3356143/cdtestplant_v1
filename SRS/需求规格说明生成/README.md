# 软件需求规格说明生成器

《SRS/测试管理平台软件需求规格说明.docx》由本目录脚本生成，改内容后重跑即可，不要直接手改 docx。

## 用法

```bash
bash SRS/需求规格说明生成/rebuild.sh
```

脚本会从 `SRS/参考/参考记录.docx`（客户模板）复制一份、清空正文，按模板的样式与自动编号重建全文，
回填总页数后输出到 `build/srs-work.docx`；确认无误后复制为 `SRS/测试管理平台软件需求规格说明.docx`。

依赖 [officecli](https://github.com/iOfficeAI/OfficeCLI) 与 Python 3。重建末尾会调用
`SRS/tools/clean_docx_parts.py` 删除模板残留的未引用页眉/页脚，避免旧项目标题留在文档包内。

## 目录

| 文件 | 说明 |
|---|---|
| `srs_content_a.py` | 正文第 1~3.2 章（范围、引用文件、状态与方式、能力需求） |
| `srs_content_b.py` | 正文第 3.3~7 章（接口、数据、安全性、保密性、环境、资源、质量、约束、数据元素、操作、故障处理、算法、人员、培训、包装、合格性、追踪性、未决问题、注解） |
| `build_srs.py` | 把内容块编译为 officecli batch 命令流（封面、目录、标题、段落、表格） |
| `rebuild.sh` | 一键重建：清空模板 → 填内容 → 表头重复/行不跨页 → 回填页数 → 清理残留页眉页脚 |

## 结构（按 GJB 438B-2009《软件需求规格说明》）

```
1 范围           1.1 标识 / 1.2 系统概述 / 1.3 文档概述
2 引用文件
3 需求           3.1 要求的状态和方式
                 3.2 能力需求（3.2.1~3.2.10，十个业务域）
                 3.3 外部接口需求（用户/硬件/软件/通信）
                 3.4 内部接口需求      3.5 内部数据需求
                 3.6 适应性需求        3.7 安全性需求
                 3.8 保密性需求        3.9 环境需求
                 3.10 计算机资源需求   3.11 软件质量因素
                 3.12 设计和实现的约束 3.13 数据元素
                 3.14 操作             3.15 故障处理
                 3.16 算法说明         3.17 有关人员需求
                 3.18 有关培训需求     3.19 包装、运输和储存
                 3.20 其他需求
4 合格性规定
5 需求可追踪性
6 尚未解决的问题
7 注解（缩略语、术语）
```

## 内容块写法

`srs_content_*.py` 里是块列表，支持：

| 块 | 写法 |
|---|---|
| 标题 | `("h1"/"h2"/"h3"/"h4", "文本")` |
| 正文 | `("p", "文本")` |
| 列表 | `("bullet", ["条目1", "条目2"])` |
| 表格 | `("table", "表 X-Y　表题", ["表头1","表头2"], [["单元格", ...], ...], "2400,4828,2400")` |

表格列宽按比例缩放到版心宽度（9600 twips），无需精确加总。

## 注意

- 标题编号由模板样式自动生成（`numId=1`），不要在文本里手写“3.2.1”。
- 目录是 TOC 域，Word 打开时按 `updateFields` 自动刷新。
- 总页数由脚本调用 Word 重排版统计后写入。
