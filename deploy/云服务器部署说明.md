# 云服务器部署说明（子路径 /cdtestplant/）

本文记录测试管理平台在公网云服务器上的部署方式，供后续更新与排障参考。
本地开发环境（Windows + 便携 MySQL/Redis + nginx）不受影响。

## 一、部署形态

| 项 | 值 |
|---|---|
| 服务器 | `47.108.230.220`（Ubuntu 24.04.4，2 vCPU / 1.6G 内存 / 40G 盘） |
| 访问地址 | http://47.108.230.220:8081/cdtestplant/ |
| 接口地址 | http://47.108.230.220:8081/cdtestplant/api/ |
| 接口文档 | http://47.108.230.220:8081/cdtestplant/api/docs |
| 代码目录 | `/www/wwwroot/cdtestplant/app` |
| 虚拟环境 | `/www/wwwroot/cdtestplant/venv`（Python 3.13，解释器在 `/opt/uv-python`） |
| 前端产物 | `app/web/cdTMP/dist`（nginx 直接托管） |
| 备份目录 | `/www/wwwroot/cdtestplant/backup` |
| 运行用户 | `www` |

进程与端口的对应关系：

```
浏览器 → nginx(8081) ─┬─ /cdtestplant/         → 静态文件 dist（vue-router 回落 index.html）
                       ├─ /cdtestplant/api/     → 反代 127.0.0.1:8000（去掉前缀）
                       ├─ /cdtestplant/uploads/ → 反代 127.0.0.1:8000（附件，后端校验 JWT）
                       └─ /cdtestplant/static/  → Django 静态（tinymce、ninja 文档资源）
                       ↑ 另有根路径 /api/ 与 /static/，用于兼容 Swagger 文档页生成的绝对地址

127.0.0.1:8000  waitress（systemd 服务 cdtestplant，run.py 启动）
127.0.0.1:3306  MySQL 8.4（apt，Oracle 官方源）
127.0.0.1:6379  Redis 7（apt，验证码 / 登录失败锁定 / 一次性下载令牌 / 接口去重）
```

## 二、与本地环境的差异

| 差异 | 说明 |
|---|---|
| LDAP | 公网不可达，`.env` 中 `ENABLE_LDAP_AUTH=false`，只保留数据库账号登录（`ModelBackend`） |
| AI 辅助 | 接口地址 `192.168.0.63:8777` 属内网，公网不可用 |
| 数据库账号 | 专用账号 `cdtp_app`，只授权 `chengdu_test_plant_v1` 库，非 root |
| 数据库版本 | 服务器 MySQL 8.4.13；Django 6.1 要求 ≥ 8.4，Ubuntu 仓库自带的 8.0 不可用 |
| 前端构建 | 用 `npm run build:server`（`--mode server` 加载 `.env.server`），base 为 `/cdtestplant/` |
| 静态/媒体目录 | `settings.py` 已改为项目内的 `static/`、`uploads/`（原为 `BASE_DIR/../../`，Linux 上会落到根分区） |

## 三、首次部署步骤（已执行，留档备查）

1. 系统依赖：
   ```bash
   apt-get install -y build-essential pkg-config libldap2-dev libsasl2-dev \
                      default-libmysqlclient-dev mysql-server redis-server rsync
   ```
2. MySQL 换 8.4（Oracle 官方源，密钥用 `RPM-GPG-KEY-mysql-2025`）：
   ```bash
   echo "deb [signed-by=/etc/apt/keyrings/mysql.gpg] https://repo.mysql.com/apt/ubuntu/ noble mysql-8.4-lts" \
       > /etc/apt/sources.list.d/mysql.list
   apt-get install -y mysql-community-server
   ```
   低内存调优写在 `/etc/mysql/mysql.conf.d/zz-cdtestplant-lowmem.cnf`
   （`innodb_buffer_pool_size=128M`、`max_connections=50`、关闭 `performance_schema`）。
3. Python 3.13：
   ```bash
   curl -LsSf https://astral.sh/uv/install.sh | sh
   uv python install 3.13
   mv ~/.local/share/uv/python/* /opt/uv-python/     # 必须移出 /root，否则 www 用户无法执行
   uv venv --python /opt/uv-python/cpython-3.13.16-linux-x86_64-gnu/bin/python3.13 /www/wwwroot/cdtestplant/venv
   ```
4. 依赖安装：`pyproject.toml` 里 `python-ldap` 锁的是 Windows 轮子，**服务器上不能用 `uv sync`**，
   改为读取依赖清单装（python-ldap 从源码编译）：
   ```bash
   REQS=$(python3 -c "import tomllib;print(' '.join(tomllib.load(open('pyproject.toml','rb'))['project']['dependencies']))")
   uv pip install --python /www/wwwroot/cdtestplant/venv/bin/python \
       --index-url https://mirrors.aliyun.com/pypi/simple $REQS
   ```
5. 数据库导入：
   ```bash
   mysql -ucdtp_app -p chengdu_test_plant_v1 < backup/cdtp_db.sql
   ```
6. 服务：`systemctl enable --now cdtestplant`（单元文件 `/etc/systemd/system/cdtestplant.service`，
   `WorkingDirectory` 必须是 `app/` —— 文档生成代码用 `Path.cwd()/'media'` 取模板）。
7. nginx：站点片段在 `/www/server/panel/vhost/nginx/extension/testplantAI.com/cdtestplant.conf`，
   由宝塔站点 `testplantAI.com`（8081）的 vhost 以 `include` 引入，未改动原 vhost 正文。

## 四、日常更新流程

```bash
# 1. 本地构建前端（改了前端才需要）
npm --prefix web/cdTMP run build:server

# 2. 本地打包（排除 venv / node_modules / .git / dist 可执行包）
tar --exclude='__pycache__' --exclude='*.pyc' -czf cdtp.tar.gz \
    apps base cdtestplant_v1 conf utils templates static deploy manage.py run.py \
    pyproject.toml uv.lock media web/cdTMP/dist

# 3. 上传并解包
scp cdtp.tar.gz root@47.108.230.220:/www/wwwroot/cdtestplant/backup/
ssh root@47.108.230.220 'cd /www/wwwroot/cdtestplant/app && \
    tar xzf ../backup/cdtp.tar.gz && chown -R www:www /www/wwwroot/cdtestplant && \
    systemctl restart cdtestplant'
```

依赖有变化时，在服务器上重跑第三、四步的 `uv pip install`。

## 五、日常运维命令

```bash
systemctl status cdtestplant          # 后端状态
journalctl -u cdtestplant -n 100 -f   # 后端日志
nginx -t && systemctl reload nginx    # 改 nginx 后必须校验再重载
mysql -uroot -e "show status like 'Threads_connected';"
redis-cli -n 1 keys '*' | head
```

备份：数据库按 7.1.9 的备份页面或 `manage.py auto_backup` 执行；
服务器上的原始导入包与 MySQL 8.0 数据目录快照在 `/www/wwwroot/cdtestplant/backup/`。

## 六、部署过程中踩到的坑（排障参考）

| 现象 | 原因 | 处理 |
|---|---|---|
| MySQL 初始化失败 `Unable to create temporary file inside "/tmp"; errno: 13` | `/tmp` 权限被改成 `drwxr-xr-x`（非 1777），mysql 用户不可写 | `chmod 1777 /tmp` |
| `redis-server: error while loading shared libraries: libjemalloc.so.2: failed to map segment` | `/usr/local/lib` 下一份 2016 年手工编译的 jemalloc 5.0.1 抢在系统库前加载，新内核下 TLS 分配失败 | 移走旧库到 `/root/backup-libs-20261021/` 后 `ldconfig` |
| `Can't open the log file: Permission denied`（redis） | `/var/log/redis` 下日志属主为 root，服务以 redis 用户运行 | `chown -R redis:adm /var/log/redis` |
| `NotSupportedError: MySQL 8.4 or later is required (found 8.0.46)` | Django 6.1 的硬性要求 | 换装 MySQL Community 8.4 LTS |
| `Failed to execute .../venv/bin/python: Permission denied` | uv 装的解释器在 `/root/.local/share/uv/python`，`www` 无法穿越 `/root` | 移至 `/opt/uv-python` 并重建 venv |
| Swagger 文档页白屏 | ninja 生成的 openapi/静态地址是根路径，子路径部署下打不到 | nginx 增加根路径 `/api/`、`/static/` 规则 |
